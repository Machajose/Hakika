# Questions to ask

## For your friend who built on Avalanche
1. Which network and wallet setup did you use, and which faucet worked for you? Can you send us a little Fuji test AVAX or a coupon?
2. Did you store hashes only, or other data on-chain? Anything you would do differently?
3. How did you protect the issuing key? Did you use a multi-signature wallet or a vault?
4. Did you hit nonce, gas, or RPC rate-limit problems, and how did you solve them?
5. How did you handle revocation and corrections?
6. How did you verify the contract source on the explorer, and is it worth doing for a demo?
7. Would you recommend batch anchoring (Merkle trees) for a graduating class? Any library you trust?
8. How much did real-network recording cost per document when you tried it?
9. What would you check before showing this to a university?

## For the registrar / examinations office
1. Which documents does MUT issue today (degree, transcript, provisional results, clearance, status letters), and in what form (printed, PDF, system-generated)?
2. How do employers and other universities verify MUT documents today, how long does it take, and how many requests per month?
3. Have there been forged MUT documents? How were they found? (Ask only for general patterns, not personal details.)
4. Who officially signs and approves each document type?
5. What does the graduation clearance process look like today (which offices, in what order, how long)?
6. Would you sponsor a pilot with fake data? What approvals would a real pilot need?

## For ICT
1. Which ERP/system holds student, fee, library and hostel data? Does it have an API, report export, or database view we could read from?
2. Who is the vendor, and is any extension or integration allowed or already planned?
3. Does MUT already have a policy for cloud hosting, data protection, and use of external services?
4. Who is MUT's data protection officer / data controller for student data?
5. Is there an existing MUT verification page or QR code scheme we should align with?
6. Would MUT host the final system on its own cloud account, so it does not depend on student accounts?

## For a lecturer or legal adviser
1. What is the legal status of electronically verifiable certificates in Kenya, and how should a prototype describe itself?
2. Are there rules about publishing student information (even salted fingerprints) on a public network?

## For your Oracle account
1. What exactly does the student package include, what are the limits, and **when does it expire**?
2. Which regions and resource types are available (Autonomous DB, compute shapes, Vault, Object Storage)?
3. What happens to the resources and data after the package ends?
